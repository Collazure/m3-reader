# GUI / TUI 工程结构

文档版本：1.4；2026-10-25。资源和 GUI / TUI 主体已实现；Ubuntu 实机验证待完成。
需求依据见 REQUIREMENTS.md，调研证据见 KNOWN_INFO.md。

## 当前目录

```text
m3-reader/
├── prts_tool/                # 现有 Python 实现，含 OCR 脚本和集中路径定义
├── prts_crawler.py           # 当前 CLI 入口
├── pyproject.toml            # 核心与可选 GUI / TUI 依赖
├── docs/                     # 需求、已知信息、架构及使用说明
├── resources/
│   ├── collected/prts_text/ # PRTS 自动采集文本；manifest 与索引随数据
│   ├── collected/terra/     # PRTS 自动采集说明和长图
│   ├── ocr/terra_text/       # terra 图片 OCR 文本，链接到采集原图
│   ├── local/                # 大地巡旅、参考文本和用户手动导入资料
│   └── updates/new/          # 最近一次实际写入内容
├── scripts/                  # Windows / Ubuntu GUI 与 TUI 启动脚本
├── bin/windows/              # Windows 可直接启动的 GUI 和 CLI 可执行程序
├── bin/ubuntu/               # 在 Ubuntu 构建后生成同样的可执行程序
├── installpacks/             # Windows 便携包、Ubuntu 源码安装包；不含资源正文
├── tests/                    # 资源链接、搜索、历史和本地替换验证
├── workspace/                # 更新历史、本地意见和替换前版本
├── CHANGELOG.md
└── README_剧情爬虫.md
```

默认资源根由 `prts_tool/paths.py` 相对于源码位置确定；`M3_READER_HOME` 可指定项目根。
自定义 `--out` 仍可覆盖文本输出根。`terra_text` 原图链接随迁移修复。
本地意见和替换前版本位于 `workspace/`，采集资源不被手动替换操作覆盖。

## 共用能力与界面

采集器 → 更新服务 → 内容历史 / 资料登记 / 搜索 / 本地意见 → CLI、GUI、TUI。
界面共用相同服务，避免三套更新逻辑。现有日志逐步补充结构化进度、结果与取消状态。
写入采用完整落盘后替换，并防止多个界面同时更新同一资源库。

GUI 使用 PySide6；左侧目录树，中间多标签阅读区，侧边或底部展示搜索、差异、意见和任务。
默认采用用户 Notepad++ 风格的绿色配色、Maple Nerd Font、行号和阅读高亮，
结合《明日方舟》的面板层级和状态标识。PDF / 图片原件保持原色。

TUI 使用 prompt_toolkit，显式 tui 子命令进入；无参数 CLI 显示帮助，便于脚本与终端使用。
窄终端切换面板，宽终端并排；支持中文输入、搜索、差异和意见编辑。
图片/PDF 提供系统查看器打开动作，不能假设终端支持内联图像。

## 更新历史和定位

每次运行记录 ID、参数、时间、来源范围、状态和失败项，包括无变化及中断运行。
内容变更保存资源 ID、完整相对路径、旧新版本、类型和逐行差异；删除行展示旧版，
新增或修改行可跳到相应版本。正文只因抓取时间变化时不计为正文更新。
历史按实际变化存储文本，图片和 PDF 用哈希、元数据及版本引用管理，避免每次复制全库。
本地导入替换单独记录来源和版本；不把导入记录描述为网站采集更新。

搜索结果统一携带资料 ID、版本、行号或页码及片段。OCR 命中关联到原图或 PDF 页；
当前逐页 OCR 只支持可靠页定位时，不宣称支持原图中的精确框选。
本地意见保存原文片段和版本，以便更新后重新定位；不能只保存容易漂移的行号。
